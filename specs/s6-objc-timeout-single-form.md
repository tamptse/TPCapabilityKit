## Problem Statement

An ObjC caller faces one timeout promise but two stored truths. The descriptor holds the timeout twice: once as the resolved enum form and once as the optional value inside the wrapped domain descriptor. Three readings come out — the collapsed display value, the explicitness flag, and the domain optional that travels to Deadline construction — but they read off two stores that must stay in sync by construction across two creation paths (plain and client-id) plus the live-view wrap of an already-resolved Swift descriptor. A reviewer asking "does display agree with what the scheduler will execute?" must prove the two stores agree in every init, and each future init or copy is a drift risk: one store updated without the other silently splits display from scheduling. On top of that, the display reading is lossy — an unspecified timeout displays as the pinned compat literal — so feeding display back into a wire init without the explicitness flag promotes unspecified to explicit, and that hazard is not stated once anywhere today (it surfaces only as test-only wrap-then-read behavior).

## Solution

Keep one stored timeout truth per descriptor and derive all three readings from it, with no expiry semantics change: the wrapped domain optional becomes the single stored form while the collapsed display reading, the explicitness flag, and the domain reading become three thin derivations over that one optional plus the single pinned literal. The mapper-internal timeout form keeps owning the wire fork once (wire-negative means unspecified, every non-negative wire travels as explicit, the omitted call arrives as the pinned compat literal collapsing to explicit) and both descriptor creation paths keep sharing one resolve-then-build sequence through it — only the storage collapses, not the policy. The lossy display round-trip (unspecified displays as the pin; rebuilding from display alone without the flag promotes to explicit) is documented once beside the single pin and pinned by one round-trip test. The configured-default contract stays untouched: Swift nil still resolves to the configured default once at Deadline construction, the pinned literal never follows a reconfigured default, and the single race stays the only expiry seam.

## User Stories

2. As an ObjC consumer, I want a negative timeout to mean unspecified, so that the scheduler configured default applies at execution.
3. As an ObjC consumer, I want an explicit timeout (including one equal to the pin literal) to travel unchanged, so that my chosen value is never reinterpreted.
4. As an ObjC consumer, I want the collapsed display reading plus the explicitness flag to tell unspecified apart from explicit-pin, so that display parity never confuses the two cases.
5. As an ObjC consumer, I want the lossy display hazard stated once, so that I know to rebuild with the explicitness flag rather than feeding display alone back into a new descriptor.
6. As a scheduler maintainer, I want one stored timeout form per descriptor, so that no future init or copy can split display from scheduling.
7. As a scheduler maintainer, I want three thin derived readings over the one stored optional, so that the next timeout tweak touches derivations adjacent to the single store, not a sync protocol between two stores.
8. As a scheduler maintainer, I want the mapper to keep owning the wire fork once, so that descriptor creation stays a thin resolve-then-build translator.
9. As a scheduler maintainer, I want both creation paths (plain and client-id) plus the live-view wrap to share the single store, so that cancel-by-id and plain scheduling cannot disagree on timeout meaning.
10. As a reviewer, I want display, explicitness, and domain to review in one hop over one optional, so that confirming the fork never leaves the descriptor observable seam.
11. As a reviewer, I want exactly one pin literal referenced by the display derivation, so that no second literal can drift out of sync with the compat promise.
12. As a reviewer, I want the `@objc` surface (collapsed timeout, explicitness flag, both constructors, both wait entries) unchanged in signature, so that no ObjC call-site migration is needed.
13. As a test author, I want the existing timeout suites to stay green without semantics edits, so that the single-form collapse is proven by pinned observable behavior rather than new seams.
14. As a test author, I want one round-trip pin proving display-fed rebuild promotes while flag-guarded rebuild preserves, so that the lossy hazard is locked, not just documented.
15. As a Settlement reviewer, I want Deadline construction plus the single race untouched, so that resolve-once, won-gated read, and stored-nil guarantees read the same as before.
16. As a future deepener, I want policy-once plus store-once plus readers-thin locality, so that the next Bridge change lands in the mapper core or the single store, not across synced duplicates.

## Implementation Decisions

- **Module**: the mapper module keeps owning the whole ObjC timeout fork behind its interface (wire-negative to unspecified, non-negative to explicit, omitted pin collapsing to explicit, domain vs display vs explicitness readers, stored-value mapping, single pin constant). The descriptor becomes a thinner translator: it keeps wrapping the domain descriptor as its single stored timeout truth and derives all readings from the stored optional. No new module is introduced.
- **Interface**: the single wire resolver stays the sole policy statement. The three descriptor observables — collapsed display reading, explicitness flag, and domain optional that travels downstream — become three thin derivations over the one stored optional (absent displays as the pin and flags non-explicit; present travels unchanged and flags explicit). No derivation restates the wire fork condition independently.
- **Stored form**: the wrapped domain optional is the single stored form; the separate stored enum field is deleted. Storing the enum and deriving the domain descriptor on demand was considered and rejected: it would force the descriptor to warehouse every non-timeout field separately (or rebuild identity on each access, risking identifier instability), while storing the domain descriptor preserves identity, capabilities, priority, retry, and metadata with zero extra state and matches exactly what downstream distinguishes (absent vs present). At rest there is one timeout truth, not two that must be kept in sync.
- **Depth**: depth decreases by one stored field plus its sync obligation. No new abstraction is added; both creation paths keep calling the same resolve-then-build sequence (resolve wire once through the mapper fork, build the domain descriptor from the resolved form) and the live-view wrap keeps mapping the already-resolved optional without touching the wire fork.
- **Seam**: the highest seams stay where they are. Tests keep crossing the descriptor observable seam (collapsed reading plus explicitness flag plus domain optional) and the wait-delivery seam (schedule-and-wait vs run-when-available through the one delivery core) plus Deadline construction. No new seam is created.
- **Adapter**: no adapter change. The Bridge remains the single ObjC scheduling adapter behind the live view; capability translation, priority coercion, descriptor assembly, and completion delivery (given queue or main) gain no timeout policy. Timeout policy lives entirely behind the mapper interface.
- **Locality**: the fork reads once behind the mapper interface; the three derivations read adjacent to the single stored optional plus the single pin reference; both creation paths resolve adjacent to the shared build. A reader confirms omitted vs wire-negative vs explicit without hopping between synced stores.
- **Lossy display**: the display derivation is documented once as lossy beside the single pin: unspecified displays as the pin literal, so a display-fed rebuild without the explicitness flag collapses to explicit pin by construction. Rebuilding with the flag (absent flag travels as wire-negative, present flag travels as display value) preserves the distinction. Turning display into a third state or making it round-trip losslessly was rejected because downstream only distinguishes absent from present and the compat promise requires omitted to travel as explicit pin.
- **`@objc` surface care**: the collapsed timeout property, the explicitness flag, both descriptor constructors, and both wait entries keep their signatures verbatim. Internal storage collapse never renames, removes, or deprecates a public selector; any future deprecation is a separate decision with its own migration note.
- **Respects ADRs**: omitted pins compat literal as explicit while wire-negative stays unspecified resolved once at Deadline construction (authoritative fork statement; whole fork reads once behind the mapper interface — this change tightens storage from two truths to one without reopening the pin promise); single scheduling adapter plus single view (thin translators, one live view, one delivery core) constrains the collapse to storage plus derivations; Deadline-owned expiry plus time-module-owned adapters (single race for wait and execution, timeout resolved once, adapters behind one sleep seam) forbid any expiry-ward drift.
- **Respects glossary**: Bridge stays the single scheduling adapter behind the live view with thin descriptor creation paths; Tasks keeps park, Deadline expiry, activation, and the Settlement step; Deadline resolves once at construction from task plus configured default; whole-set readiness stays behind the registry wait interface.

## Testing Decisions

- A good test pins externally observable timeout behavior (omitted reads as the pin and flags explicit, negative stores absent and flags non-explicit while displaying the pin, explicit travels unchanged, both constructors agree, run-when-available agrees with schedule-and-wait, Swift-absent wrap displays as pin flagged non-explicit, display-fed rebuild promotes while flag-guarded rebuild preserves) through the descriptor observables plus Deadline construction and the deterministic clock, never the stored field shape or lock internals — except one mechanical check proving a single stored timeout truth remains at rest.
- Modules under test: descriptor observables (both constructors, live-view wrap of a Swift-absent descriptor, client-id identity), mapper resolver (omitted vs negative vs explicit, both-paths-share), wait entries (negative-unspecified and explicit through run-when-available), Deadline construction (Swift absent vs omitted pin vs negative against a non-default configured default), plus the new round-trip pin (lossy display promotion vs flag-guarded preservation).
- Prior art: the ObjC mapper suite, the timeout-contract suite, the timeout-pins suite, and the single-view suite are the models for any touched test. The collapse must keep every one green with zero test-semantics edits; only the new round-trip pin plus the single-store mechanical check are additive, and both cross existing seams (descriptor observables, Deadline construction).
- Verification for the storage collapse: full suite green with zero behavior edits; the resolver, display-collapse, contract, and pins suites pass unchanged, proving the omitted-vs-negative-vs-explicit triple and the Deadline resolve-once behavior survived. Any suite naming the removed duplicate store fails the ticket.
- Verification for the round-trip pin: the new test asserts the hazard explicitly (wrap Swift-absent, read display pin flagged non-explicit, rebuild from display alone yields explicit pin; rebuild honoring the flag yields absent again) so the lossy derivation is locked against future "fixes" that would invent a third state.

## Out of Scope

- Any change to timeout resolution (task value vs configured default), to the pinned-compat literal value, or to the wire-negative-means-unspecified rule.
- Any change to Deadline construction, the single race, the sleep seam, the Settlement decision table, retry budget, void policy, or slot-release ownership.
- Any change to the registry wait interface, park mechanics, activation gates, generation sharing, or whole-set readiness.
- Any `@objc` signature rename, removal, or deprecation; any Swift-side domain descriptor shape change.
- Collapsing the time module into Deadline, threading time per call, or forking virtual time per generation.
- Renames beyond the collapse or formatting churn.

## Further Notes

- Grill record (autonomous self-grill, no user round — decisions derive from the dual-store inventory plus the pinned-omitted promise and Deadline-owned expiry; no prototype):
  - Q: Wire-negative vs explicit vs omitted-pin — what must survive? A: Three wire classes collapse to two downstream states: wire-negative travels as absent (scheduler default applies at Deadline construction); omitted arrives as the pin literal and every non-negative wire including the pin literal travels as present pinned-or-chosen value. Downstream distinguishes absent from present only, so explicit-pin vs omitted indistinguishability is intentional compat, not a bug to fix.
  - Q: Why does dual storage drift? A: Two truths (stored enum plus wrapped optional) must agree in every init today by construction; any future init, copy, wrap, or refactor that touches one without the other splits what display claims from what the scheduler executes. One store removes the sync obligation instead of documenting it harder.
  - Q: Which single form — wrapped optional or stored enum? A: Wrapped optional wins. Explicitness equals presence exactly under both construction and live-view mapping, and display equals stored-or-pin exactly, so the enum adds no information downstream. Storing the enum would force warehousing or recomputing every non-timeout field (identity instability risk); storing the domain descriptor keeps identity plus all payload fields with one field deleted and zero new state.
  - Q: Round-trip absent-to-display-to-explicit hazard — real or test-only today? A: Real shape, test-only trigger today: wrapping a Swift-absent descriptor displays the pin, and feeding that display into a wire init without the flag promotes to explicit pin. No prod path does this today (wait entries build from wire plus flag-aware stores, not from display), but the derivation is lossy by construction so it must be stated once and pinned by test before a future caller trips it in prod.
  - Q: Does the mapper lose the fork? A: No — mapper keeps the fork. The resolver stays the sole policy statement; only the descriptor-side duplicate store goes. Readers-thin means derivations, not policy, move.
  - Q: Cut-now alternatives challenged — (a) keeping both stores with a sync assertion was rejected because assertions catch drift after the fact while single-store makes drift unrepresentable; (b) making display lossless via a third state was rejected because downstream only distinguishes absent from present and compat requires omitted to read as explicit pin; (c) deleting the explicitness flag in favor of display-only was rejected because display collapses absent and explicit-pin to the same literal and reviewers would lose the only disambiguator. Load-bearing constraints: single resolver owns the wire condition once, one stored optional, three derivations adjacent to it, single pin reference, lossy statement once, `@objc` frozen.
- Vocabulary: module (mapper timeout detail, Bridge view, Tasks path), interface (resolver seam, descriptor-observable seam, wait-delivery seam), depth (one fewer stored field), seam (single resolver, single store, single delivery core, single race untouched), adapter (Bridge as single ObjC adapter, live vs virtual behind one sleep seam), leverage (existing resolver plus contract plus pins suites as the verification seam), locality (policy once, store once, readers adjacent).
- Source of decisions: no prototype; decisions derive from the pinned-omitted promise and its follow-up, the current Bridge files (mapper resolver plus readers, descriptor with two constructors plus two observables over a duplicated store, scheduler with dual build paths into one delivery core), and the frozen expiry contract.

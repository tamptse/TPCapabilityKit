## Problem Statement

A reviewer asking "how does a scheduled Task move from queued to parked to active to terminal?" must cross five modules plus two injected closures to assemble one answer: the scheduling facade (schedule/enqueue/schedule-and-wait/cancel), the Path flow (process/park/wait/activate/settle), the lifecycle table (LifecycleStore plus its nested OrderIndex), the expiry type (Deadline), the slot admission seam (scoped hold), and the registry whole-set wait (waitForAll with an injected expiry race). Each hop is a drift risk: the Deadline type is shallow (37 lines restating its own implementation — resolve-once plus one race shared by waiter and executor); the OrderIndex nests three deep inside the lifecycle table while mirroring its bookkeeping (rows, order queues, and counts snapshot must agree on every move); and the pure extractions (`gateAdmitted` / `isAvailable` / `dequeueNext`) hide the TOCTOU window across the hold suspension instead of stating it once beside the flow.

## Solution

Give the lifecycle depth one review surface with two separable moves, ordered by confidence: (a) deepen the lifecycle table into its own module folding the order index inside (counts plus place plus order under one invariant, one Place transition), with Path as the only flow reader; and/or (b) collapse Deadline into a Path-private race helper (the registry keeps receiving the race as a value and never names the type). No behavior change: queued/parked/active/terminal reachability, priority FIFO order, park double-park and waiter-cancel rules, single-expiry sharing between capability wait and execution, slot admission and scope-exit release, retry identity, waiter delivery, and counts agreement are identical before and after. Deletion test: deleting the Deadline type or inlining the OrderIndex changes nothing observable through the public scheduling seam.

## User Stories

1. As a Tasks maintainer, I want the queued-to-parked-to-active-to-terminal flow to read in one place, so that I stop hopping five modules plus two closures to answer one lifecycle question.
2. As a reviewer, I want one Place transition to audit instead of three agreeing bookkeeps (rows, order, counts), so that move/order/rows cannot silently disagree.
3. As a reviewer, I want the expiry race stated once beside the flow that shares it, so that waiter-vs-execution sharing needs no hop into a 37-line type.
4. As a capability waiter, I want park, expiry, activation, and settlement to keep behaving identically, so that missing capabilities still park once, expire once, and deliver waiters exactly once.
5. As a priority scheduler, I want high-before-low FIFO order preserved verbatim, so that the fold changes addresses not ordering.
6. As a slot operator, I want scoped-hold admission, FIFO wake, cancellable wait, and scope-exit release untouched, so that concurrency limits behave identically before and after.
7. As a retry integrator, I want retry re-queue through the same Lease identity preserved, so that completions and live Bridge views survive a retry.
8. As a cancel caller, I want parked-waiter cancellation and terminal delivery unchanged, so that cancel still lands expired with one delivery.
9. As a registry consumer, I want whole-set readiness to keep receiving the expiry race as a value, so that the registry never names the Tasks expiry type.
10. As a test author, I want lifecycle depth proven by behavior through the public schedule/cancel/wait seam, so that the collapse is verified by outcomes not by type spelling — except one mechanical grep proving Deadline gone or OrderIndex inlined.
11. As a speculative-caution reviewer, I want the OrderIndex fold explicitly marked Speculative, so that it only lands if the single-invariant review payoff is demonstrated and ADRs 0007/0017/0025/0026 revisit triggers stay unmet.
12. As a future contributor, I want Path as the only flow reader of the deepened table, so that no second flow path can re-split the invariant.
13. As a TOCTOU auditor, I want the entry-check vs post-admission re-check window stated once beside the activation flow, so that pure extractions stop hiding it.
14. As an ADR reader, I want the change traceable to single-source-of-truth ordering, internal order index, and parked colocation decisions, so that the deepen/collapse clearly respects prior decisions rather than reopening them.
15. As an N1/N4 sequencer, I want this work ordered after terminal-unify and slot-eviction-unify on the same Path/Lifecycle core, so that no concurrent edit re-splits the flow being deepened.

## Implementation Decisions

- **Module**: Tasks remains the deep module behind the schedule/cancel/pending/active seam. The lifecycle table deepens into its own module folding the order index inside; Path remains the only flow reader (process/park/wait/activate/settle). No new public module is introduced; the race helper (if collapsed) is a Path-private function.
- **Interface**: the public scheduling seam is unchanged (schedule/schedule-and-wait/cancel/pending/active plus result rendezvous). The internal change is (a) OrderIndex ceases to be a separately addressable nested type — enqueue/dequeue/remove become private mechanics of the single table transition — and/or (b) Deadline ceases to be a named cross-seam type — timeout still resolves once from task plus configured default, one race still shared by capability wait and execution, now spelled as a Path-private helper passed as a value across the registry wait seam.
- **Depth**: depth decreases by one named type per move (Deadline gone; OrderIndex gone as a named seam) with zero new abstraction. The lifecycle table gains one invariant (counts plus place plus order agree on every transition) stated once beside the single Place transition; the expiry path loses one hop with identical race semantics.
- **Seam**: the highest seam stays the Tasks schedule/cancel/pending/active facade plus the single result rendezvous and the registry whole-set wait. Tests cross that seam; no new seam is created. The lifecycle table remains the single writer: each Lease mutation happens together with its row write in one locked transition.
- **Adapter**: no adapter change. The Bridge live Lease view, ObjC timeout mapping, and time live/virtual adapters plus advance policy are untouched; deterministic-time spelling stays on the facade.
- **Locality**: park double-park and waiter-cancel rules stay in the table beside the single transition; the budget/policy plus row transition adjacency from N1 is preserved; the TOCTOU window (entry availability check vs post-admission re-check across hold suspension) is stated once beside the activation flow instead of hidden inside pure extractions.
- **Leverage**: leverage is reviewer locality plus drift removal: one invariant to audit, one race to audit, zero cross-type sync (move vs order vs rows; Deadline vs Path vs registry). Risk is bounded because both moves are spelling-only — same priority queues, same snapshot derivation, same race topology — only addresses change.
- **Ordering**: Deadline collapse is Worth-exploring and goes first; OrderIndex fold is Speculative and goes second, blocked by the first, so the speculative half can be dropped without losing the first half's payoff.
- **Depends on N1+N4**: same Path/Lifecycle core — terminal unify (single Terminal vocabulary, fused decide-then-transition) and slot-eviction unify (single scoped-hold/retire discipline) land first; this spec assumes their post-state and must not re-split what they fused.
- **Respects ADRs**: ADR-0007 (one source of truth per question; count derives) constrains the fold to keep one counts snapshot derived from the single transition; ADR-0017 (order index as private mechanics with single counts snapshot; place/order/counts cannot disagree) is the invariant the fold must preserve verbatim, not reopen; ADR-0025/0026 (Store colocation parked with pre-drawn seams; no fourth lock domain or renewed friction) forbids promoting the deepened table into a Store-level split or a new lock domain — it stays a Tasks-internal module.

## Testing Decisions

- A good test crosses the public Tasks seam and asserts externally observable behavior (queued/parked/active/terminal reachability, high-before-low order, double-park refusal, waiter cancel on terminal, shared-expiry timeout vs win, slot admission plus scope-exit release, retry identity preservation, cancel lands expired, counts agreement), never the spelling of the collapsed type or the nesting depth of the order index — except one mechanical grep proving the Deadline type is gone (collapse) or no separately addressable OrderIndex remains (fold).
- Modules under test: lifecycle table transitions (insert/dequeueNext/park/activate/retry/terminal with counts agreement), Path flow (process/park/wait/activate/settle as one path), expiry sharing (capability wait and execution share one timeout), slot admission (scoped hold across the TOCTOU window).
- Prior art: lifecycle suites (LifecycleTable double-park plus counts, LifecycleTransition, Lease matrix, Settlement and Settlement-guards), path locality proof (park/withdraw/cancel/retry single-delivery plus freed slot), determinism suites (virtual-time timeout, execution expiry, priority high-before-low, slot serialization, cancel-pins-expired, generations preservation), expiry suites (resolve-once construction, execution expiry delivery, operation-wins-race), activation-gate and slot-hold suites (admission refusal, TOCTOU re-check, FIFO wake, cancellable wait). The deepen/collapse must keep every one green with zero test-semantics edits.

## Out of Scope

- Any change to lifecycle reachability (which states are legal from pending vs parked vs active), priority ordering, retry budget or void-completion policy, waiter preservation or exactly-once delivery, slot limits or release ownership (stays with activation scope-exit), expiry resolution (task timeout vs configured default), or time adapters.
- Changing the public `State`/Terminal shape, the Bridge live-view reflection, State creation/observation, registry emission order or lock discipline, generation prune or shared-slot coupling, or deterministic-time spelling.
- Splitting the Store facade, introducing a scheduler protocol, adding a fourth lock domain, or any formatting churn beyond the deepen/collapse.
- Reopening ADRs 0007/0017/0025/0026: no revisit trigger is met by this work; the Speculative half (OrderIndex fold) must be dropped rather than force a revisit.

## Further Notes

- Deletion test is the acceptance bar: deleting the Deadline type (callers read only the Path-private race helper) or inlining the OrderIndex (callers read only the single table transition) changes nothing observable through the public seam.
- If Deadline-collapse vs race-helper naming is contested during implementation, prefer a race-named private spelling over an expiry-named type, because the contract is one shared race between waiter and executor, not a standalone expiry object.
- If the OrderIndex fold is contested, prefer keeping ADR-0017 verbatim (private mechanics plus single snapshot) over a broader table rewrite: the fold is address consolidation, not invariant redesign.
- Source of prototype decisions: none — no prototype; decisions derive from the five-module plus two-closure hop inventory and ADR-0007/0017/0025/0026.
